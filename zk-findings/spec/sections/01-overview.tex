\section{System overview and actors}
\label{sec:overview}

This section fixes the vocabulary used throughout the specification: the
components that make up the system, the pipeline that carries a value transfer
from a wallet to an on-chain state update, and the actors together with the
trust boundaries that separate them. Everything stated here is what the code
\emph{enforces}; where README prose or a source comment states an intent that
the code does not back, a spec delta records the gap.

\subsection{What the system is}

The repository implements a shielded value pool that proves its own state
transitions with hash-based STARKs and settles them on an EVM chain by
replaying the proof under the native \code{keccak256} opcode
\src{README.md:3-6}. The settlement contract stores a block counter and two
32-byte roots, the commitment-tree root \code{currentRoot} and the
nullifier-map root \code{currentNullifierRoot}
\src{contracts/src/ShieldedPool.sol:70-77}. Both roots are taken from the
verified statement and only checked for continuity; the contract never
re-derives or opens either tree \src{contracts/src/ShieldedPool.sol:151-166}.

In the code paths that the client prover, the node and the wallet actually
use, every shielded-layer digest is the Poseidon2 sponge $\Hp$ (Section~\ref{sec:primitives})
applied to the 16-bit little-endian limb encoding of a byte preimage
\src{crates/pq-hash/src/poseidon.rs:100-111}\src{crates/pq-hash/src/poseidon.rs:225-238}:
\begin{align}
  \mathsf{cm} &= \Hp\bigl(\code{DOMAIN\_NOTE} \,\|\, \mathsf{value}_{\mathrm{LE},8} \,\|\, \rho \,\|\, \psi \,\|\, \mathsf{pk}_d\bigr),
  \label{eq:ov-cm}\\
  \mathsf{nf} &= \Hp\bigl(\code{DOMAIN\_NULLIFIER} \,\|\, \mathsf{sk}_d \,\|\, \rho\bigr).
  \label{eq:ov-nf}
\end{align}
The preimage orders are fixed by \code{Note::commit} and \code{Note::nullifier}
\src{crates/shielded/src/note.rs:108-127}; the Poseidon2 instantiation is
selected by the callers, \code{Poseidon2Commitment} for (\ref{eq:ov-cm}) and
\code{Poseidon2Shielded} for (\ref{eq:ov-nf})
\src{crates/prover/src/client.rs:147-155}\src{crates/prover/src/client.rs:204}\src{crates/node/src/main.rs:276-279}\src{crates/pq-hash/src/shielded.rs:98-105}.
The commitment tree and the nullifier map are both Poseidon2-hashed
\src{crates/prover/src/client.rs:119-124}; the empty nullifier map is the
depth-96 Poseidon2 empty-subtree root, pinned in the contract as
\code{EMPTY\_NULLIFIER\_ROOT} \src{contracts/src/ShieldedPool.sol:79-86}.
Spend authorization is an SLH-DSA (SPHINCS+, parameter set \code{Sha2\_128f})
signature over a canonical statement encoding
\src{crates/pq-sign/src/spend\_auth.rs:89-94}\src{README.md:37-38}.
No elliptic-curve primitive is used by the proof, hash or signature crates
\src{README.md:3-5}; signing of the L1 settlement transaction is delegated to
the RPC endpoint, the node holding no L1 key
\src{crates/node/src/settlement.rs:10-17}. End to end the demonstration
covers per-transfer STARKs, a block proof that recursively verifies its
children and folds their statements into one digest, and SNARK-free EVM
settlement \src{README.md:29-54}.

\subsection{Pipeline}

Two WHIR configurations are used. The client and recursion layer
(\code{InnerWhirConfig}) runs a Poseidon2 duplex challenger over the width-16
KoalaBear Poseidon2 permutation (rate 8)
\src{crates/prover/src/whir\_recursion.rs:83-84}\src{crates/prover/src/whir\_recursion.rs:103};
the settlement layer (\code{whir::Config}) runs a Keccak-256
\code{SerializingChallenger32} over \code{HashChallenger} with
\code{Keccak256Hash} \src{crates/prover/src/whir.rs:72-77}. Only the Keccak
layer is replayed on the EVM \src{.scratch/pq-shielded-rollup/map.md:90}. The
path from a transfer to a settled state update is a four-stage composition.

\begin{enumerate}
\item \textbf{Client transfer proof.} The spender proves one transfer locally
  as a \code{p3\_circuit\_prover::BatchStarkProof} under \code{InnerWhirConfig}
  and retains the matching \code{CircuitVerifier}
  \src{crates/prover/src/client.rs:76-81}\src{crates/prover/src/client.rs:119-124}
  (README names the proving crate \code{p3-multi-stark} \src{README.md:39-40}).
  This layer is asserted at compile time to run with HVZK blinding
  \src{crates/prover/src/lib.rs:109-113}. Each spend draws a nullifier
  non-membership witness against the nullifier map before the nullifier is
  inserted \src{crates/prover/src/client.rs:197-212}, and the claimed
  post-append commitment root is computed from the pre-append frontier that
  the circuit re-derives \src{crates/prover/src/client.rs:143-163}\src{contracts/src/ShieldedPool.sol:15-18};
  the binding of the append position is examined in \finding{H-02}.
\item \textbf{Block / recursion circuit.} The block circuit re-verifies each
  child proof in-circuit through the vendored \code{WhirRecursionBackend}
  \src{crates/prover/src/block.rs:103}\src{crates/prover/src/block.rs:425}\src{README.md:41-45},
  constrains child $i$'s \code{root\_after} to equal child $i{+}1$'s
  \code{root} and chains the nullifier roots likewise
  \src{crates/prover/src/block.rs:60-85}, and folds the child statements
  \src{crates/prover/src/block.rs:273-290}:
  \begin{equation}
    r_0 = 0^{8},\qquad r_i = \Hp\bigl(r_{i-1} \,\|\, \mathsf{stmt}_i\bigr)\ (1 \le i \le n),\qquad
    \code{statementRoot} = r_n,
    \label{eq:ov-fold}
  \end{equation}
  a digest of eight base-field elements exported as 16 little-endian 16-bit
  limbs (D-089) \src{crates/prover/src/block.rs:292-305}. A block has
  $n \ge 1$ children \src{crates/prover/src/block.rs:331-333}\src{contracts/src/BlockStatement.sol:82}. The child
  verifier object is supplied alongside each child proof; its pinning is
  examined in \finding{V-06}.
\item \textbf{Keccak re-expression and on-chain replay.} The block proof is
  produced under the Keccak settlement configuration
  \src{crates/prover/src/whir\_recursion.rs:615-627}, which is asserted at
  compile time to be non-ZK \src{crates/prover/src/lib.rs:102-107}
  (cross-reference \finding{M-10}). The generated Solidity \code{WhirVerifier}
  replays \code{p3\_batch\_stark::verify\_batch} on one Keccak sponge that runs
  the batch phases and then every WHIR opening round without reseeding
  \src{contracts/src/verifier/WhirVerifier.sol:10-11}\src{contracts/src/verifier/WhirVerifier.sol:39-46}\src{contracts/src/verifier/WhirVerifier.sol:282-303}.
\item \textbf{Settlement.} \code{ShieldedPool.applyBlock} reverts unless the
  injected verifier returns \code{true}, decodes the statement, requires
  $\code{rootBefore} = \code{currentRoot}$ and
  $\code{nfRootBefore} = \code{currentNullifierRoot}$, overwrites both stored
  roots with \code{rootAfter} and \code{nfRootAfter}, increments
  \code{blockNumber}, and emits \code{BlockApplied} carrying the four roots and
  the decoded total fee \src{contracts/src/ShieldedPool.sol:144-178}. The fee
  is only emitted, and the decoded \code{statementRoot} is neither stored nor
  emitted (cross-reference \finding{L-04}).
\end{enumerate}

The block statement carried across stages 2--4 has the fixed layout and length
\begin{align}
  \mathsf{stmt}_{\mathrm{blk}} &= \bigl[\, n,\ (\mathsf{in}_i, \mathsf{out}_i)_{i<n},\ \code{statementRoot},\ \code{rootBefore},\ \code{rootAfter}, \notag\\
  &\qquad \code{nfRootBefore},\ \code{nfRootAfter},\ (\code{fee}_i)_{i<n} \,\bigr], \\
  |\mathsf{stmt}_{\mathrm{blk}}| &= 1 + 2n + (1+4)\cdot 16 + 4n = 81 + 6n,
\end{align}
where every digest occupies 16 limbs (limb $j$ holds digest bytes $2j$ and
$2j{+}1$, low byte first) and every fee 4 limbs read as a little-endian
\code{uint64}; the decoder requires $1 \le n \le 2^{16}-1$, an exact length
match, and every decoded limb $\le \code{0xffff}$, and sums the fees into
\code{totalFee}
\src{contracts/src/BlockStatement.sol:11-15}\src{contracts/src/BlockStatement.sol:63-111}\src{contracts/src/LimbCodec.sol:16-64}\src{crates/prover/src/block.rs:265-271}.
The length is independent of how many nullifiers and outputs each transfer
carries \src{contracts/src/BlockStatement.sol:65-68}.

\subsection{Node HTTP surface}

The router registers the eight routes of Table~\ref{tab:endpoints}, attaches
the authentication and rate-limit guard as a route layer (it runs only for
matched routes), a CORS layer allowing \code{GET}/\code{POST} with the
\code{Authorization} and \code{Content-Type} headers, and a request-body limit
of $1\,048\,576$ bytes
\src{crates/node/src/main.rs:717-741}\src{crates/node/src/main.rs:90}. The guard
answers 404 for a path absent from the ACL, 401 for a missing, malformed,
badly MACed or expired token, 403 for an insufficient role, and 429 when the
limiter bucket keyed by $(\text{role}, \text{path})$ is exhausted
\src{crates/node/src/main.rs:543-581} (cross-reference \finding{M-11}).
A token is
\begin{align}
  \mathsf{tok} &= \mathrm{b64url}(m) \,\|\, \texttt{.} \,\|\, \mathrm{b64url}\bigl(\mathrm{HMAC\text{-}SHA256}(k, m)\bigr), \\
  m &= \mathsf{role}\ (1\ \text{byte}) \,\|\, \mathsf{expiry}\ (8\ \text{bytes, LE}),
\end{align}
verified in the order format, MAC (constant-time), payload length 9, role
byte, expiry \src{crates/node/src/auth.rs:13-15}\src{crates/node/src/auth.rs:190-211}\src{crates/node/src/auth.rs:236-253}.
The ACL is deny-by-default and maps each exact path to the minimum role
\src{crates/node/src/auth.rs:256-302}. The three roles are totally ordered,
$\code{ReadOnly} = 0 < \code{Submitter} = 1 < \code{Admin} = 2$, with the access
test $\text{role} \ge \text{required}$
\src{crates/node/src/auth.rs:56-65}\src{crates/node/src/auth.rs:219-234}.

\paragraph{Permissionless settlement.}
\code{applyBlock} is declared \code{external} with no caller restriction: any
account may submit a \code{(statement, proof)} pair, and beyond the verifier's
boolean the only checks are statement decoding and root continuity against
stored state \src{contracts/src/ShieldedPool.sol:144-157}. The event carries
only the block number, the four roots and the total fee
\src{contracts/src/ShieldedPool.sol:92-99}. The soundness of the system
therefore rests on what the verifier binds; the adequacy of this gate is
examined in \finding{H-01}.

\paragraph{Verifier bound to the proof bundle, not the circuit.}
The injected verifier consumes a single caller-supplied bundle: a 16-byte
header (magic \code{WBND}, a version byte, and the CONFIG and PROOF word
counts, accepted versions 5, 7 and 8), then the \code{CONFIG} and \code{PROOF}
sections and a \code{STATEMENT} section prefixed by its own u32 word count
\src{contracts/src/verifier/WhirVerifier.sol:13-19}\src{contracts/src/verifier/WhirVerifier.sol:219-257}.
\code{CONFIG} holds the batch framing prefix (seed, degree bits, preprocessed
digest, grind difficulties), each opening round's schedule and framing labels
\src{contracts/src/verifier/WhirVerifier.sol:23-25}, and the constraint
programs consumed by the constraint-identity check
\src{contracts/src/verifier/WhirVerifier.sol:305-318}. The contract reads
\code{CONFIG} from calldata and does not pin it; the source comment only
recommends that a deployment pin $\Hk(\code{configSection})$
\src{contracts/src/verifier/WhirVerifier.sol:21-25}\src{contracts/src/verifier/WhirVerifier.sol:259-265}.
Because the circuit description the verifier replays is taken from the same
bundle a caller supplies, the binding between the on-chain verifier and the
honest block circuit is not established on-chain; this is examined in
\finding{V-01}.

\begin{specdelta}
The security-model prose states that the chain trusts ``the operator set
allowed to call \code{applyBlock}'' \src{README.md:160-162}. The deployed
contract contains no such set: \code{applyBlock} carries no access-control
modifier and no operator mapping, so settlement is permissionless in the code
as written \src{contracts/src/ShieldedPool.sol:144} (cross-reference
\finding{H-01}, \finding{I-02}). Likewise, the constructor comment describes a
Keccak depth-256 empty nullifier root \src{contracts/src/ShieldedPool.sol:114-118},
whereas the code substitutes the pinned depth-96 Poseidon2 constant
\src{contracts/src/ShieldedPool.sol:79-86}\src{contracts/src/ShieldedPool.sol:134-135};
and the verifier's header comment names wire version 3
\src{contracts/src/verifier/WhirVerifier.sol:13} while the code accepts only
versions 5, 7 and 8 \src{contracts/src/verifier/WhirVerifier.sol:242}.
\end{specdelta}
